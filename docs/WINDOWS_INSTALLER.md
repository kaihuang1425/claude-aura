# Windows installer

Claude Aura uses a conventional per-user Windows installer built with Inno
Setup 7. This document is the maintenance and release contract for future
installer work.

Installer work does not close HUMAN CHECKPOINT D, replace live Aura review, or
declare the product release-ready.

## Public distribution paths

Claude Aura has three possible public Windows distribution paths plus one
non-public development build. They must never be presented as providing the
same identity guarantee. A no-certificate release uses one GitHub release with
both the unsigned Setup and ZIP/CMD assets; it does not create two releases for
one version.

| Path | Public use | Entry point | Trust boundary |
| --- | --- | --- | --- |
| Unsigned native Setup | Optional guided path without a signing certificate | `Claude-Aura-Setup-v<version>-UNSIGNED.exe` | Native wizard and Installed apps registration; explicit unsigned warning plus SHA-256 and manifest, but no Authenticode publisher identity |
| Checksummed release ZIP | Public fallback without a signing certificate | Extract the attached `claude-aura-v<version>.zip`, then run `Install Claude Aura.cmd` | Readable source scripts plus SHA-256 integrity; no Authenticode publisher identity and no Installed apps registration |
| Signed native Setup | Optional when a CA-trusted certificate is available | `Claude-Aura-Setup-v<version>.exe` | Authenticode publisher, timestamp, final-file SHA-256, and native Installed apps registration |
| Unsigned development Setup | Never public | `Claude-Aura-Setup-v<version>-UNSIGNED-DEV.exe` | Local developer inspection only; `releaseEligible: false` |

For a no-certificate release, publish the public unsigned Setup with its
matching `.sha256` and `.manifest.json`, plus the deterministic allowlisted ZIP
and its `.sha256`. GitHub's automatic **Source code** archives are not
substitutes. The unsigned Setup filename, first wizard page, manifest, README,
security guidance, troubleshooting, and release notes must all state that
Windows cannot verify its publisher. If Windows warns about or blocks it, the
user must stop and use the ZIP/CMD fallback instead of bypassing the warning.

The user verifies the ZIP, extracts the whole archive, and runs the `.cmd`
beside its bundled `windows` folder. Never publish the `.cmd` alone.

`Install Claude Aura.cmd` resolves only the adjacent `windows\install.ps1`,
changes to a safe local working directory, and applies `ExecutionPolicy Bypass`
only to that PowerShell process. The installer validates the shipped app
surface, performs a guarded app-tree replacement, and creates owned Start and
Desktop shortcuts. It does not claim a signed publisher or add an Installed
apps entry. The matching `Uninstall Claude Aura.cmd` and Start-menu shortcut
remain the removal path.

## User experience

Setup must look and behave like an ordinary Windows application installer:

- native title bar, buttons, task dialogs, keyboard order, and high-contrast
  fallback;
- light or dark appearance following Windows;
- the real Claude Aura icon and truthful signed or unsigned publisher status;
- no UAC request; Setup stops with a clear message if launched elevated;
- no downloader, service, scheduled task, driver, browser extension, firewall
  change, or Claude Desktop modification;
- explicit Node.js 22-or-newer and Microsoft Edge WebView2 Runtime prerequisite
  checks; Node runs only from a validated absolute executable path;
- the exact application and local-data locations before installation;
- optional Desktop shortcuts and normal Start menu shortcuts; and
- a normal **Installed apps** entry and native uninstaller.

The one custom visual signature is the thin eight-colour theme spine on the
welcome artwork. Everything else stays quiet and Windows-native. The palette is
Aura aubergine `#2F2937`, coral `#D66D4B`, cream `#F4DFBB`, and the eight
launcher accent colours generated by `scripts/build-installer-assets.mjs`.
Text uses Segoe UI; paths use Consolas.

Never add fake shields, “100% safe” claims, invented verification badges, ads,
bundled offers, urgency, hidden downloads, or Anthropic as the publisher.

## Ownership and transaction model

One component owns each persistent surface:

| Owner | Persistent surface |
| --- | --- |
| `installer/app-transaction.ps1` | Atomic replacement of `app` only |
| Inno Setup | Start/Desktop shortcuts, `ClaudeAura` AppUserModelID, versioned maintenance helpers, Installed apps registration, and native uninstaller |
| Aura at first launch | Initial `data/config.json` and normal runtime state |
| `windows/uninstall.ps1` | Guarded removal of the app and, only with explicit consent, local data |

Setup writes below:

```text
%LOCALAPPDATA%\ClaudeAura
|-- app\                     application files
|-- data\                    settings and technical logs
|-- webview\                 Aura's separate WebView2 sign-in profile
`-- installer\
    |-- backend-<version>\    retry-safe maintenance helpers
    `-- uninsNNN.exe          native uninstaller
```

The install sequence is:

1. `scripts/build-release.mjs` creates the allowlisted Aura ZIP.
2. `scripts/build-installer.mjs` re-hashes and safely extracts that exact ZIP,
   regenerates deterministic wizard art, and invokes the pinned compiler.
3. Inno Setup expands the signed, CRC-protected payload to its private Temp
   directory.
4. `app-transaction.ps1` copies every payload file to a unique stage, verifies
   SHA-256 and length, rejects reparse points, writes an atomic journal, and
   swaps the app directories.
5. Inno creates its shortcuts, Installed apps entry, maintenance files, and
   native uninstaller.
6. At `ssPostInstall`, Inno writes the exact transaction ID to a finalization
   marker and its own Installed apps key. Either correlation proves that
   transaction—not an older same-version registration—reached native
   finalization.
7. The helper commits by deleting the previous app backup.

If Setup fails or is cancelled before native finalization,
`DeinitializeSetup` invokes rollback and restores the previous app tree. If the
process or computer stops unexpectedly, the next Setup or native uninstall
resolves the journal first. A finalized transaction is committed; any earlier
phase is rolled back. Rollback records `rollingBack` and `rolledBack` states so
cleanup can be retried after the old app has already been restored. The
transaction tests exercise byte-exact rollback, same-version correlation,
cleanup retry, and clean commit in a disposable `%LOCALAPPDATA%`.

Keep the stable AppId
`{49DD4496-1ABF-5202-B127-3D7E919318C5}`. Changing it creates a second Installed
apps identity and breaks normal upgrades.

Setup uses `PrivilegesRequired=lowest` and `ArchitecturesInstallIn64BitMode=win64`.
This keeps registration in HKCU and launches native PowerShell/WebView2 on
64-bit Windows while retaining 32-bit Windows support. Setup rejects an
already-elevated launch rather than silently producing an admin-bound
uninstaller.

## Launch surface

Claude Aura is currently a PowerShell-hosted WinForms/WebView2 application.
Shortcuts therefore invoke the absolute native Windows PowerShell path with
`-NoProfile -STA -ExecutionPolicy Bypass -WindowStyle Hidden -File` and the
exact installed `aura-ui.ps1` path. `Bypass` applies only to that process; Setup
does not change machine or user execution-policy settings. The hidden window is
the unused console, not Aura or Studio.

A future native launcher is a trust-hardening milestone, not a cosmetic file
rename. It must be built from reviewed source with a pinned compiler, remain
per-user and offline, launch only the exact installed script, preserve useful
startup errors, add no service or persistence, and be staged before release.
The public launcher must be signed and timestamped with the same expected
publisher as Setup, and its signer/hash must be recorded in the installer
manifest. Keep the current launch path until clean-VM upgrade, rollback,
keyboard, scaling, and actual Aura launch gates pass for the replacement.

## Uninstall and retry safety

Uninstall first asks whether to keep local data. The default removes the app
and shortcuts while retaining `data` and `webview`. The destructive choice is
explicit and cannot be undone.

The native uninstaller runs the versioned maintenance copy of
`windows/uninstall.ps1`, which lives outside the `app` tree it removes. It
first recovers any interrupted install transaction. If cleanup fails, Inno
aborts before removing its Installed apps registration or maintenance helper,
so the user can fix the cause and retry.

`Uninstall Claude Aura.cmd` remains the ZIP-install fallback. When native
registration exists, its PowerShell entry point validates the exact HKCU
AppId, the `%LOCALAPPDATA%\ClaudeAura\installer` parent, the `uninsNNN.exe`
filename, and the absence of a reparse point before delegating to the native
uninstaller. It never removes the app while leaving a valid native registration
behind.

## Pinned build tool

The build is pinned to the official Inno Setup `7.0.2` x64 compiler. The builder
rejects a different `ISCC.exe` SHA-256 or an invalid compiler publisher
signature.

- Official installer:
  `https://github.com/jrsoftware/issrc/releases/download/is-7_0_2/innosetup-7.0.2-x64.exe`
- Installer SHA-256:
  `5AD54CA3DEF786F8F4212552E54CC6D8D61329E2D24A1CFEE0571D42C2684FF1`
- Pinned `ISCC.exe` SHA-256:
  `0FF6140D641F84B64204A2C4D52207C6FC437C9F4DB8779C83083D84F7E3D70D`
- Expected compiler publisher: `Pyrsys B.V.`

Verify the compiler installer with Inno Setup’s
[official instructions](https://jrsoftware.org/isdl-verify.php) before running
it. The compiler is build-time only and is never bundled with Aura.

## Routine one-click build

After changing Aura, double-click:

```text
installer\Build Installer.cmd
```

The helper runs `npm.cmd run check`, verifies all eight built-in themes in
Light and Dark, and builds the current allowlisted public release ZIP. After a
successful build, File Explorer selects the ZIP under `release\`. Users extract
it and run `Install Claude Aura.cmd`.

The command-line equivalent is:

```powershell
& '.\installer\Build Installer.cmd' --no-open --no-pause
```

Use `--signed` only after configuring the signing variables below. Use
`--unsigned` for the clearly marked public unsigned Setup and
`--unsigned-dev` only for the local-development Setup. Use `--zip` to state the
default ZIP/CMD mode explicitly. A no-certificate release runs both `--zip`
and `--unsigned`; each invocation reruns the same repository and theme gates.
The helper never changes `package.json`, creates a commit, or publishes
anything.

## Unsigned public build

The public unsigned Setup requires an explicit command:

```powershell
npm.cmd run installer:unsigned
```

It produces:

```text
release\Claude-Aura-Setup-v<version>-UNSIGNED.exe
release\Claude-Aura-Setup-v<version>-UNSIGNED.exe.sha256
release\Claude-Aura-Setup-v<version>-UNSIGNED.manifest.json
```

The manifest must say `buildType: "unsigned-release"`,
`releaseEligible: true`, `distribution.trust: "sha256-only"`, and
`signing.status: "NotSigned"`. The build must also produce the matching public
ZIP and checksum from the same payload.

This is a convenience path, not a verified-publisher path. Its filename and
first wizard page must say that it is unsigned. Publish all five companion
assets in one GitHub release, state the exact hashes in the release notes, and
keep ZIP/CMD as the fallback. Never imply that SHA-256 authenticates the
publisher, never suppress Windows warnings, and never tell users to bypass
SmartScreen.

## Unsigned development build

Unsigned output must require an explicit development command:

```powershell
npm.cmd run installer:dev
```

It produces:

```text
release\Claude-Aura-Setup-v<version>-UNSIGNED-DEV.exe
release\Claude-Aura-Setup-v<version>-UNSIGNED-DEV.exe.sha256
release\Claude-Aura-Setup-v<version>-UNSIGNED-DEV.manifest.json
```

The manifest must say `buildType: "unsigned-development"`,
`releaseEligible: false`, and `signing.status: "NotSigned"`. Never publish or
rename this artifact as the recommended installer, and never tell users to
bypass SmartScreen.

## Signed public build

A public installer requires a CA-trusted Authenticode code-signing certificate
whose publisher identity matches the advertised publisher. A self-signed
certificate is for private testing only; users must never be asked to install a
root certificate.

Use a certificate-store or managed-signing command with an RFC 3161 timestamp.
Do not place a PFX password, token PIN, or signing-service credential in the
repository or command text.

```powershell
$env:AURA_SIGNTOOL_COMMAND = '"C:\Program Files (x86)\Windows Kits\10\bin\<sdk>\x64\signtool.exe" sign /fd SHA256 /td SHA256 /tr <timestamp-url> /sha1 <thumbprint> /d "Claude Aura" $f'
$env:AURA_SIGNER_THUMBPRINT = '<40-character-certificate-thumbprint>'
npm.cmd run installer
```

Use single quotes around `AURA_SIGNTOOL_COMMAND` so `$f` remains literal. The
release build:

1. re-verifies the release ZIP SHA-256 from the bytes it extracts;
2. compiles and signs Setup plus the generated uninstaller;
3. verifies the staged executable before any Setup output is promoted to
   `release`;
4. requires Authenticode status `Valid`;
5. requires the exact expected signer thumbprint;
6. requires a timestamp certificate;
7. hashes only the final signed executable; and
8. promotes Setup, checksum, and manifest as one rollback-safe output set, then
   records the payload, compiler, signer, timestamp, and release eligibility in
   the manifest.

Windows SmartScreen reputation is separate from visual quality. A valid
signature gives users a verifiable publisher, but a new certificate or
low-volume artifact can still need reputation. Follow Microsoft’s
[SmartScreen guidance](https://learn.microsoft.com/windows/apps/package-and-deploy/smartscreen-reputation);
never claim the UI can suppress a warning.

## Required verification

Every installer change must pass:

```powershell
node tests/installer.test.mjs
npm.cmd run check
npm.cmd run verify:cycle
npm.cmd run release
npm.cmd run installer:unsigned
npm.cmd run installer:dev
git diff --check
```

Parse every edited PowerShell file and inspect the generated executable:

```powershell
$tokens = $null
$errors = $null
[void][Management.Automation.Language.Parser]::ParseFile(
  (Resolve-Path .\installer\app-transaction.ps1),
  [ref]$tokens,
  [ref]$errors)
if ($errors.Count) { $errors | Format-List; exit 1 }

Get-AuthenticodeSignature .\release\Claude-Aura-Setup-v0.3.0-UNSIGNED-DEV.exe
Get-FileHash -Algorithm SHA256 .\release\Claude-Aura-Setup-v0.3.0-UNSIGNED-DEV.exe
Get-AuthenticodeSignature .\release\Claude-Aura-Setup-v0.3.0-UNSIGNED.exe
Get-FileHash -Algorithm SHA256 .\release\Claude-Aura-Setup-v0.3.0-UNSIGNED.exe
```

The signed command is an additional gate only when publishing a signed Setup.
The checksummed ZIP remains the public fallback for a no-certificate release;
an unsigned developer Setup never replaces either public unsigned artifact.

Before public distribution, use a clean Windows VM or Windows Sandbox to test:

- fresh install, same-version repair, upgrade, injected install failure, and
  hard-interruption recovery;
- no unexpected UAC or network activity;
- `en`, `zh-CN`, and `zh-HKTW`;
- the explicit unsigned title/subtitle in each of those locales;
- keyboard-only navigation, 100/150/200% scaling, dark mode, and high contrast;
- optional Desktop shortcuts and Start menu shortcuts;
- Installed apps publisher, version, icon, and uninstall action;
- launch into the actual Aura WebView2 app on live `claude.ai`;
- uninstall while Aura is open;
- a failed destructive uninstall followed by a successful retry;
- uninstall with data retained; and
- uninstall with data removed in a disposable profile.

Whole-window Aura evidence remains governed by `docs/SCREENSHOT_PLAN.md`. An
installer screenshot proves only installer UI, not Aura behavior.

## Future change checklist

For every future installer change:

1. keep the AppId, fixed product root, per-user boundary, and elevation refusal;
2. preserve one owner per persistent surface;
3. keep app prepare/commit/rollback journaled, atomic, idempotent, and
   reparse-safe;
4. keep uninstall helpers versioned and outside the app tree;
5. keep setup offline and free of services, tasks, drivers, and hidden
   persistence;
6. update `en`, `zh-CN`, and `zh-HKTW` independently;
7. regenerate and byte-check deterministic artwork;
8. update installer tests, the public file manifest, release integration,
   README, security guidance, and troubleshooting;
9. build the explicitly named unsigned development artifact for local UI
   inspection;
10. build and inspect the public unsigned wizard in every shipped installer
    locale when it will be a release asset;
11. inspect the actual wizard, not a mockup;
12. run the clean-VM lifecycle matrix;
13. create the public ZIP through `npm.cmd run release`, public unsigned Setup
    through `npm.cmd run installer:unsigned`, or signed Setup through the
    signed command; and
14. publish checksums only from the final distributed bytes, after signing and
    timestamping when the artifact is a signed Setup executable.

If any boundary changes, document the reason and updated threat model before
implementation.
